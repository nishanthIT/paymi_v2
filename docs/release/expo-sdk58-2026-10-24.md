# Expo Go SDK 58 compatibility — 24 October 2026

The iOS error came from opening an SDK 57 project in SDK 58 Expo Go. At the start of this fix, an interrupted upgrade had also left `package.json` requesting SDK 58 while installed React Native, Expo Router and other modules still belonged to SDK 57.

Completed the dependency upgrade to Expo 58.0.19, React 19.3.0, React Native 0.88.0 and Expo's matching native packages, Metro config, ESLint config and React types. A fresh lockfile resolved the stale-install peer dependency conflict without `--force` or `--legacy-peer-deps`; `npm ci` installed it successfully. The existing `.env` and backend were not changed.

Source compatibility changes retain React Native's new strict TypeScript API: use instance ref types, the current list-viewability type, optional list header/footer values and refresh callbacks that return `Promise<void>`. Tab icons retain their existing active/inactive theme colors. Missing list indices are ignored when calculating chat date headings. Certificate saving now awaits SDK 58's asynchronous file write and handles a rejected write before reporting success.

## Open the upgraded project

Stop any old Metro process with Ctrl+C. From `paymi_v2`, run:

```sh
npx expo start --go --clear
```

Close and reopen Expo Go on the iPhone, then scan the new QR code. Do not reuse a development server that was started before the upgrade. Other checkouts must run `npm ci` after pulling the new lockfile.
